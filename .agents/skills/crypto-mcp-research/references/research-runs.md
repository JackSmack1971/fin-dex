# Reproducible research-run format (v1, extended)

Each run is a local directory containing `manifest.json` and retained artifacts. The manifest is described by `assets/research-run.schema.json`; validate it with `python scripts/validate_research_run.py path/to/manifest.json`. The validator is offline. `--replay` uses retained fixtures only and cannot invoke MCP, HTTP, or other providers.

The manifest records task identity, UTC start/completion, canonical asset identity, research horizon, methodology version, configuration references, repository provenance, selected specialists and their execution statuses/handoff paths, evidence-ledger paths, synthesis revision and digest, review bindings, verdict, artifacts and calculations. At most three specialists may be listed. Reviews bind to the frozen synthesis only after collection closes and reconciliation completes. The two independent reviewer roles remain `adversarial_reviewer` and `evidence_verifier`. Partial, blocked, failed, or open runs remain valid records; they do not imply successful research.

Every artifact entry stores its path relative to the manifest directory, kind, and lowercase SHA-256 of exact retained file bytes (`sha256`). Structured artifacts may also carry `logical_sha256`, the digest of canonical JSON. Canonical serialization is UTF-8, sorted object keys, compact separators `(',', ':')`, Unicode preserved, and NaN/Infinity rejected. Physical digests change with whitespace/newlines; logical digests do not. The manifest is not self-hashed. Paths must stay inside the run directory. Digests detect changes but are not signatures or tamper-proof storage.

Replayable observations require stable IDs, values, units, and UTC `observed_at_utc` timestamps. Each replayable calculation records a versioned formula, ordered input IDs, timestamp and source-fixture mappings, output unit, sampling window, rounding method, missing-data behavior, expected value, and tolerance. Missing, mismatched, unitless, non-finite, or zero-baseline inputs cannot silently pass. If retained inputs are insufficient, record `status: NOT_REPLAYABLE` and exact `missing_inputs`; the validator reports `BLOCKED` rather than attempting reconstruction.

Supported formulas are `simple_return.v1` and `percent_change.v1` (`(end/start-1)*100`), `benchmark_relative_return.v1` (asset gross return divided by benchmark gross return, minus one, in percent), `bid_ask_spread.v1` (spread divided by midpoint, in percent), and `sampled_extrema.v1` (minimum and maximum of all supplied samples). V1 requires `rounding: python_round_half_even.v1` and an integer `rounding_digits` from 0 to 15; the result or each extremum is rounded with Python's binary64 `round` implementation before tolerance comparison. Input units must match for the supported formulas. No implicit fill, provider call, or current-value lookup occurs.

The validator reports `PASS`, `FAIL`, or `BLOCKED`. A partial lifecycle record can pass structural validation when its state is explicit. Legacy handoffs and evidence ledgers remain accepted unchanged. Old calculations without replay metadata are treated as blocked for replay; they are never silently upgraded.

For Git workspaces record the revision captured for that run. If Git metadata is unavailable, set repository status to `UNAVAILABLE`, revision to null, and give a reason. Do not invent repository identity. Configuration references are descriptive paths or IDs; retain their content as a hashed artifact if exact configuration reproduction is required. No files are uploaded and no provider is contacted during validation or replay.
