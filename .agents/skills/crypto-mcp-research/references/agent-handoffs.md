# Agent handoff and synthesis contract

All six native Codex agents use the shared version 1 schema at `assets/handoff.schema.json`. First validate saved-file persistence and handoff shape with `python scripts/validate_handoff_artifact.py handoff.json`; then validate collection/review lifecycle with `python scripts/validate_handoffs.py handoff.json [--synthesis contract.json]`. Artifact generation, successful persistence, schema validation, and lifecycle acceptance are separate states. A missing, empty, malformed, or nonconforming file is never a successfully persisted artifact. `COMPLETE`, `PARTIAL`, `FAILED`, and `BLOCKED` describe task execution only; none asserts evidence success. Claim evidence retains the existing `CORROBORATED`, `SINGLE_SOURCE`, `CONFLICTED`, `UNVERIFIED` statuses; `UNAVAILABLE` describes provider/observation access.

Each claim references observation IDs. Observations capture source, exact tool, upstream provenance when available, asset and venue identity, metric/value/unit, source observation and retrieval UTC times, and methodology/coverage when available. Set `observed_at_utc` to null when the provider supplies no observation time; never substitute retrieval time. Unknown provenance or methodology remains null or omitted; do not fabricate it. Tool call summaries record successes, failures, unavailable providers, and tools not called. A `CORROBORATED` ledger claim requires distinct documented upstream origins and documented measurement methods. For claims typed `TOKEN_CONTRACT_IDENTITY` or `ON_CHAIN_IDENTITY`, it also requires explicit compatible chain IDs. Chain qualification is not universally required for market prices or exchange instruments. Provider count or a matching contract string alone cannot establish independence; retain `SINGLE_SOURCE` when independence is unknown.

For every observation produced through a local REST adapter, save the exact adapter response as a JSON file in the research run before closing specialist collection. Include an `evidence_artifacts` reference with a run-relative path, SHA-256 of the stored bytes, and the exact response `source_url`. The reference must resolve beside/under the handoff's run directory; the saved response's provider, URL, and retrieval time must agree with the observation. `prepare-review` binds these response hashes into its permit and rejects missing, changed, mis-timed, or out-of-run references. This links the retained response to the observation metadata; it does not automatically prove that every summarized value was derived correctly, so reviewers must still inspect the response and claim methodology. Never use a later response as if it were the specialist's original observation.

## Collection and review lifecycle

The primary agent alone owns scope, dispatch, specialist collection, reconciliation, synthesis, and final conclusions. Dispatch only relevant specialists, with at most three concurrent specialists. Agents do not delegate recursively. Close specialist collection only after every selected specialist has returned a structurally valid handoff; statuses may be PARTIAL, FAILED, or BLOCKED and must not be rewritten as COMPLETE. Reconcile those reports before freezing a synthesis revision. Only then may the adversarial reviewer and evidence verifier run.

Reviewer handoffs must include `review.synthesis_revision`, the frozen synthesis SHA-256, the exact `claim_ids` reviewed, and `review.dispatch_permit_sha256` from the permit returned by `prepare-review`. Final validation checks that reviewer binding against the permit payload digest, so changing raw evidence and editing its permit record after dispatch invalidates the existing reviewer returns. Freeze the input as a canonical JSON value: serialize with sorted keys, compact separators, UTF-8, then compute lowercase SHA-256. Store both snapshot and digest with revision ID. These checks detect accidental mismatch and post-dispatch edits that do not also replace reviewer returns; they do not make storage tamperproof or authenticate reviewers, and Codex does not natively enforce immutability. Validators check declared structure and bindings, not that review reasoning is correct or that observations are true.

The synthesis contract accepted by the validator has `synthesis_owner`, `specialist_phase` (`state`: `OPEN` or `CLOSED`, `expected_agent_ids`), `reconciliation.completed`, `revision` (`id`, `snapshot`, `sha256`), and `reviews`. Select at most three specialists. Review entries must not be present until collection is closed and reconciliation is complete. All expected specialists must have submitted a handoff before closure; incomplete execution remains explicit and can prevent a defensible research conclusion. Reviewer handoffs supplied alongside the synthesis contract are checked against the revision ID, digest, and claim IDs found in the frozen snapshot.

## Native supervisor checkpoint

For native Codex orchestration, the supervisor must use `scripts/native_lifecycle.py` with a local Python interpreter. Do not use JavaScript globals or assumed host APIs for filesystem persistence or hashing: the Codex `functions.exec` isolate does not guarantee `btoa`, `crypto`, or filesystem access. The model's prose and a JSON response in the event stream do not prove that an artifact was persisted.

1. Wait for every selected native specialist thread to reach a terminal event. Save an execution receipt containing each selected `agent_id`, native thread ID, `terminal: true`, and the handoff `execution_status`.
2. Persist each returned handoff with `python scripts/native_lifecycle.py persist-handoff returned.json --output <new-path>`. The command refuses to overwrite an existing path, verifies the saved file is nonempty and parseable, and invokes `validate_handoff_artifact.py`. Preserve its receipt, including logical-content and exact stored-byte SHA-256 values. Local REST observations must reference their saved response artifacts as specified above; the review permit records and rechecks those response hashes.
3. Reconcile the validated handoffs. Write a frozen snapshot and a pre-review synthesis contract with `specialist_phase.state: CLOSED`, `reconciliation.completed: true`, the expected specialist IDs, exact snapshot, canonical digest, revision ID, synthesis owner, and `reviews: []`.
4. Run `python scripts/native_lifecycle.py prepare-review --contract <contract> --snapshot <snapshot> --execution <receipt> --handoff <path> ... --permit <new-path>`. Reviewer dispatch may follow only when the command exits 0 and prints `REVIEW_DISPATCH_ALLOWED`. It checks terminal receipts, exact selected-to-returned specialist coverage, persisted handoff validators, reconciliation, snapshot equality, canonical digest, and the pre-review lifecycle validator. On any error it exits 2 with `BLOCKED` and no permit.
5. Give both reviewers the same permit's revision, synthesis digest, dispatch permit payload digest, and exact claim IDs. Require `dispatch_permit_sha256` in each review binding. Persist and validate their handoffs, append their binding entries to the synthesis contract, and run `python scripts/native_lifecycle.py validate-review --contract <final-contract> --permit <permit> --handoff <adversarial-handoff> --handoff <verifier-handoff>`. This executes saved-artifact checks and `validate_handoffs.py --synthesis`. Also run `validate_research_run.py` when retaining a reproducible run manifest. Preserve raw native event streams alongside the supervisor receipts.

`REVIEW_DISPATCH_ALLOWED` is a deterministic supervisor checkpoint, not an authorization token and not a runtime security boundary. Codex does not currently route or intercept native collaboration calls through this script; a model can bypass it by directly calling the collaboration tool. Therefore do not claim automatic dispatch enforcement. Record the gate command and its successful output before reviewer events, and report any unmediated dispatch as a lifecycle violation.

## Native identity evidence limit

Use only identifiers actually returned by the native collaboration runtime or its event stream. Do not turn an agent role, task name, workspace path such as `/root/market_analyst`, supervisor-generated value, or handoff `task_id` into a `native_thread_id`. If the available collaboration interface exposes agent handles and terminal status but no native thread identifier or event record, the current gate requirement is unsatisfied and reviewer dispatch remains blocked. Preserve the exact unsupported field and the raw tool return.

The minimally invasive alternative, if a runtime cannot expose thread IDs, is a separately versioned supervisor receipt that binds the exact native invocation/return envelope, selected agent identity, terminal result, and saved handoff byte digest. Label that proof level `RUNTIME_RETURN_BOUND`; do not represent it as native-thread verified, and do not accept it in place of `native_thread_id` until the lifecycle contract and its review policy are explicitly revised and tested. Persisting the handoff remains mandatory either way.

## Review classification records

Recorded typed-review classifications (`RESEARCH_REVIEW`, `ENGINEERING_REVIEW`, `UNRESOLVED`, `POLICY_DECISION`) can be checked offline with `python scripts/validate_review_classification.py record.json [related.json ...]`; see [review classification validator](review-classification.md) and `assets/review-classification-record.v1.schema.json`. It checks declared structure and consistency with the controlling `AGENTS.md` policy, not review quality or truth; it is not a runtime security boundary, does not replace `prepare-review` or `validate-review`, and a research record only references the permit that `prepare-review` produced.
